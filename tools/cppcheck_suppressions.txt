# --- 6. App/ 계층 MISRA Advisory deviation (2026-07-30, 이현우) ---
#   게이트 정책 A = Required/Mandatory 만 차단, Advisory 는 리포트만.
#   cppcheck misra 애드온에 등급 필터가 없어, 실제로 뜨는 Advisory 룰을
#   근거를 달아 개별 등록한다. 폴더 통째 억제(`*:*App/motor/*`)로 돌아가지 말 것.
#
#   11.4 (포인터 <-> 정수 변환, Advisory)
#     원인: ST HAL 의 페리페럴 베이스가 `#define GPIOB ((GPIO_TypeDef*)GPIOB_BASE)`
#           형태라, GPIO/TIM/I2C 를 쓰는 모든 코드에서 구조적으로 발생한다.
#     판단: 벤더 헤더를 고치지 않는 한 회피 불가. 페리페럴 접근 자체가 목적인
#           계층이므로 deviation 으로 수용한다. (MISRA Compliance:2020 의
#           adopted code / 하드웨어 접근 예외에 해당)
misra-c2012-11.4:*App/*

#   8.7 (단일 TU 에서만 참조되는 외부 링키지, Advisory)

#           static 으로 바꾸면 계층 분리가 깨진다.
